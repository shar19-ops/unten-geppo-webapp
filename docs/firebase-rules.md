# Firebaseのセキュリティルール

`firebase/database.rules.json` がこのアプリのデータベースルールの正です。Firebase Consoleで公開しているルールと、このファイルは常に同じ内容にしてください。

## 何を守っているか、何を守っていないか

このアプリは**匿名認証**で動いています。サイトを開けば誰でも匿名アカウントが作られ、データを読み書きできます。ルールはこの「誰でも」を前提に、**壊せる範囲を狭める**ことだけを目的にしています。

| | 守っている | 守っていない |
|---|---|---|
| **書き込み** | 1リクエストでの全消去・全上書き(`/vehicles` `/logs` 全体の置き換え)。車両番号の無い車両、キーの形式に合わない月報 | 1台ずつ・1件ずつの削除や書き換え |
| **読み取り** | ルート直下の一括読み出し | 車両一覧・月報の読み取り(アプリの動作に必要なため誰でも読める) |

**読み取りは守れていません。** 運転者名・行先・メールアドレスは、サイトを開ける人なら誰でも読めます。これを守るには本物の認証(Entra ID)が必要で、それは本運用が安定した後の大幅アップデートで対応する方針です。それまでの期間はこの状態を**受容している**ことを、情シスと認識合わせしてください。

1件ずつの削除を止めないのは、アプリ自体がその操作をするためです(車両リストの削除ボタン)。そこは日次バックアップ(`docs/firebase-backup.md`)で補っています。

## ルールの内容

```json
{
  "rules": {
    ".read": false,
    ".write": false,
```

ルート直下は読み書きとも禁止。`.write` は親から子へは引き継がれますが、**子から親へは引き継がれない**ため、下で `/vehicles/$vehicleId` に書き込みを許しても `/vehicles` 全体や `/` への書き込みは拒否されます。これが「1リクエストで全消去できない」仕組みの本体です。

```json
    "vehicles": {
      ".read": "auth != null",
      "$vehicleId": {
        ".write": "auth != null",
        ".validate": "newData.hasChildren(['plateNumber', 'id']) && newData.child('plateNumber').isString() && newData.child('plateNumber').val().length > 0 && newData.child('id').val() == $vehicleId"
      }
    },
```

車両は1台単位でのみ書ける。書くときは車両番号が空でない文字列であること、`id` がキーと一致することを要求する。アプリは常に車両1台分をまるごと書くため、この条件で正規の操作は止まりません。

```json
    "logs": {
      ".read": "auth != null",
      "$logKey": {
        ".write": "auth != null && $logKey.matches(/^[^_]+_[0-9]{4}_[0-9]{1,2}$/)"
      }
    }
  }
}
```

月報は `車両ID_年_月` の形のキーにだけ書ける。アプリは `/logs/<キー>/days/<日>` と `/logs/<キー>/meta` に書きますが、`.write` は親から子へ引き継がれるのでどちらも通ります。

### アプリ側で合わせた変更

Excel取込の確定時に `/vehicles` 全体を `PUT` していた処理(`pushVehiclesToCloud`)を **`PATCH`** に変えました。`PATCH` は「名前を挙げた車両だけをそれぞれ置き換える」操作で、1台ずつ別の書き込みとして評価されるため通ります。取り込んだ一覧に無い車両が消えなくなる、という副作用がありますが、取込はマージ済みの全車両を渡しているため実質的な違いはありません。

## 公開のしかた

1. [Firebase Console](https://console.firebase.google.com/) → プロジェクト `unten-geppo-webapp` → **Realtime Database → ルール**
2. `firebase/database.rules.json` の内容をそのまま貼り付けて **公開**
3. 公開後、次のコマンドで**本番に対して**確認する

```bash
node scripts/verify-firebase-rules.mjs --post
```

このスクリプトは本番データを壊さないよう、書き込みの確認をすべて「今ある内容と同じものをETag付きで書く」か「アプリから見えない検証用キーに書いて直後に消す」のどちらかで行います。すべて `OK` になれば完了です。

> `--post` を付けずに実行すると、ルール公開前でも安全な項目だけを確認します(拒否されるべき書き込みは公開前だと通ってしまい、検証用の一時データが残る可能性があるため省略します)。

## Consoleのシミュレータで確認する場合

ルール画面の「ルールプレイグラウンド」でも試せます。**認証済み**(任意のUID)で:

| 操作 | 場所 | データ | 期待 |
|---|---|---|---|
| 書き込み | `/vehicles` | `{}` | **拒否** |
| 書き込み | `/logs` | `null` | **拒否** |
| 書き込み | `/vehicles/abc` | `{"id":"abc","plateNumber":"品川300あ1234"}` | 許可 |
| 書き込み | `/vehicles/abc` | `{"id":"abc"}` | **拒否**(車両番号なし) |
| 書き込み | `/logs/abc_2026_9/days/1` | `{"destination":"x"}` | 許可 |
| 書き込み | `/logs/bad_key/days/1` | `{}` | **拒否** |
| 読み取り | `/` | | **拒否** |
| 読み取り | `/vehicles` | | 許可 |

## ルールを変えるとき

1. `firebase/database.rules.json` を編集してPRにする
2. マージ後、Consoleに貼り付けて公開
3. `node scripts/verify-firebase-rules.mjs --post` で確認

Consoleだけ変えてファイルを変えない、またはその逆をすると、どちらが正か分からなくなります。**必ず両方**を同じ内容にしてください。
